# 产品规划：个人轻量级 Markdown 编辑器

## 产品定位

个人长期自用的轻量级 Markdown 桌面编辑器，Windows 优先、后续 Mac，核心体验是 Typora 式所见即所得（单栏渐进渲染，非左右分栏预览），并原生内建可视化 Git 版本管理面板，替代"编辑器 + 外部 Git 客户端"的两件套。

组织模型：**文件夹浏览器模式**（打开一个文件夹作为工作区，文件树浏览编辑），不做 Vault / 双向链接 / 知识图谱。

## 核心目标

- 启动快、内存低（依托 Tauri 原生 WebView，非 Electron）
- 大文件编辑不卡顿（CodeMirror 6 原生视口虚拟化 + lezer 增量解析）
- 所见即所得的 Markdown 实时渲染体验
- 内建可视化 Git 面板，写作与版本管理一体化
- 高度模块化架构，支撑"不同 AI 逐步接工开发"且新增功能不推倒重构
- 长期个人可扩展（图片管理、导出、搜索、未来插件）

## 不做什么（Out of Scope）

- 不做双向链接 / 知识图谱（Obsidian 式 Vault 心智模型）
- 不做多用户协作、云同步、账号体系
- 不做插件市场 / 插件沙箱安全体系（初期只预留扩展点，不做完整插件加载机制）
- 不做移动端
- 不追求 100% 复刻 Typora 全部主题与生态
- 不做实时多人协同编辑
- Git 功能只覆盖个人日常场景（status / diff / commit / 历史 / 分支切换 / 简单合并提示），不做 interactive rebase、cherry-pick 等复杂操作

## 与 Typora、Obsidian、MarkText 的区别

- **Typora**：纯所见即所得，无原生版本管理、无内建文件树侧栏，闭源不可定制。本项目原生集成可视化 Git，且完全可控可扩展。
- **Obsidian**：以 Vault + 双向链接为核心心智模型，插件生态庞大但基于 Electron 体积和内存开销大。本项目明确不做链接图谱，换取更轻量的 Tauri 方案和更简单的心智模型（就是文件夹）。
- **MarkText**：开源的 Typora 平替，Electron + Vue 技术栈。本项目用 Tauri 替代 Electron 换取轻量和性能，且内建 Git 面板是核心差异化能力。
- **本项目差异化定位**：轻量原生壳（Tauri）+ 大文件高性能编辑核心（CodeMirror 6）+ 版本历史内建（Git 面板）+ 为 AI 持续开发而设计的高度模块化架构。

## MVP 应具备的能力

1. 打开文件夹作为工作区，侧边栏文件树浏览/操作文件
2. 多标签同时编辑多个 .md 文件
3. CodeMirror 6 编辑核心 + 核心 Markdown 语法（标题/粗斜体/列表/任务列表/引用/分割线/代码块高亮/链接）的所见即所得渐进渲染
4. 保存/未保存状态提示
5. 图片粘贴/拖拽插入与本地资源管理
6. 完整可视化 Git 面板：状态、diff、暂存提交、历史记录、分支切换
